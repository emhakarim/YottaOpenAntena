# Licensing policy

**This is an engineering policy statement, not legal advice. Consult a lawyer
before any commercial distribution.**

## This project

OpenAntenna Studio is MIT licensed (see `LICENSE`).

## External solvers

The toolkit is designed to *drive* external electromagnetic solvers that carry
their own licences:

| Component | Licence | How this project uses it |
|---|---|---|
| openEMS | GPL-3.0-or-later | generated scripts + subprocess execution |
| CSXCAD | LGPL-3.0-or-later | imported by the *generated* script, in the user's own environment |
| nec2++ (planned) | GPL-2.0 | planned adapter, same process boundary |

## The boundary rules

1. **No vendoring.** No copyleft solver source, headers, libraries or binaries
   are copied into this repository. Third-party wheels are downloaded and
   installed from the official upstream distribution, by the user, into the
   user's own environment.
2. **No linking.** The MIT core never imports `CSXCAD` or `openEMS`. Scripts
   generated by the core import them, and those scripts run as separate
   processes on the user's machine. The core communicates with them through
   files (`project.json`, generated script, `s11.csv`).
3. **No hidden coupling.** The adapter exposes the solver as an external
   program with an explicit path (`OPENEMS_ROOT`), so the boundary stays visible
   in the code and in the run manifest.
4. **Attribution survives.** A generated script carries a header stating that it
   drives GPL/LGPL software and that the generated file itself is not part of
   OpenAntenna Studio.
5. **Distribution reality.** Shipping a bundle that contains GPL solver
   binaries alongside this MIT code creates GPL obligations for that bundle.
   If the project ever ships an installer, the recommended shape is to install
   the MIT core and the copyleft solver as clearly separate components, with the
   solver obtained from upstream.

## Why the process boundary is enough in practice

A generated script is a user-authored artefact produced by an MIT tool; the MIT
tool does not contain the GPL code and does not link against it. This is the
standard pattern used by commercial tools that drive open-source solvers. The
residual risk sits in *redistribution*, not in usage, which is why rule 5 exists.
